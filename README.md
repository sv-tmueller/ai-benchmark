# AI Benchmark — Prompt Corpus & Artifacts

A curated collection of benchmark prompts and the resulting model outputs.

Two things live here:

- **`prompts/`** — 28 TOML prompt definitions (plus one fixtures file)
  spanning coding, reasoning, math, summarization, creative-writing,
  instruction-following, game-generation, app-generation, domain-probes,
  vision, and ServiceNow-style consulting tasks.
- **`results/`** — collected outputs grouped by prompt family: playable
  HTML game/app artifacts generated by various models, and Markdown
  story/document deliverables.

### Using a prompt with `@prompts/<file>.toml`

Reference any prompt file directly, e.g. `@prompts/game-melon-jelly.toml`;
the `[system]`/`[user]` texts are plain prose and need no preprocessing.
Three caveats:

- **`param-translate`**: its placeholders (`TARGET_LANG`,
  `TEXT_TO_TRANSLATE`) are meant to be replaced with values from
  `param-translate.fixtures.toml` — each `[[cases]]` entry supplies
  `vars.*` pairs (described in the fixtures file as substituting
  `{{variables}}`). Pointing an agent straight at
  `@prompts/param-translate.toml` skips that substitution, so the
  placeholders arrive literally; fill them in yourself or substitute
  concrete values before sending.
- **`vision-shape-count`**: the `[images]` declaration is harness-only;
  when prompting ad hoc, attach `prompts/assets/shapes.png` yourself.
- **Grading**: the `[grading]` blocks in `math-addition` and
  `vision-shape-count` are consumed by the benchmark harness only;
  informal runs simply ignore them.

## Flash vs. Frontier: single-shot capability envelope

An ongoing empirical question for this corpus: how much does
single-shot generation quality degrade on flash-tier models compared
with frontier models, and where is the gap widest?

First datapoint — the GLM 5.3 Flash full-corpus sweep (Oct 2026,
batches [#37]/[#97]):

- **Coverage.** 26 of the corpus's 28 prompts ran (29 recorded
  tests); both gradable prompts PASS; probes and text tasks came back
  essentially flawless.
- **Where the cliff sits.** The degradation concentrates in LARGE
  GENERATIVE single-shot artifacts. Of the 7 nominally "playable"
  game artifacts, click-through audits verified exactly 1 (melon-jelly)
  as truly playable: 2 died at boot on shader bugs, 2 scripts were
  syntactically truncated mid-generation, and 2 crashed on entering
  gameplay. On the one apples-to-apples comparison (melon-jelly vs
  Claude Sonnet 5.5 on the same prompt), functionality was at parity
  with a clear aesthetic/polish deficit.
- **Truncation signature.** The two parse-death artifacts
  (cities-skylines, meridian-launch) were exactly the generations that
  raced the 65k reasoning/output budget — burning tens of thousands of
  hidden reasoning tokens before emitting code that cuts off
  mid-expression while the enclosing document still looks healthy.
- **Counterweight.** The best-engineered prompt (horror-house, with an
  explicit shared integration contract) yielded a 13-file project that
  rebuilt with zero defects — flash-tier brittleness scales inversely
  with prompt rigor.
- **Owner-directed takeaway.** Flash-tier variants trade deep
  single-shot reliability for speed/cost: excellent on bounded,
  well-specified tasks, degraded disproportionately on large
  single-shot generative codegen (budget starvation, unproofread long
  code, silent runtime deaths masked by healthy-looking menus/UI
  shells).
- **Practical guidance.** (a) Treat the game/app categories as the
  discriminating tier. (b) Judge playability by click-through +
  sustained animation + per-script parse — never by boot-paint alone.
  (c) Frontier models are expected to clear prompts that flash models
  fail, making those prompts the sharpest comparators.

Planned follow-up: re-running the same game/app tier on a
frontier/non-flash model; results will extend this section with a
direct comparison table.

That follow-up has since run TWICE (batches #111 and #112). The
results are summarized in the two subsections below; the full
numbers live in `results/frontier_summary.md`,
`results/gallery.html` (interactive cross-model comparison table)
and the definitive browser-verification comment on #106.

### Tier-1 comparison: GLM 5.2 vs GLM 5.3 Flash (batch #111)

The 10 discriminating game/app prompts re-run against
`vllm/release/glm-5-2` (non-flash, same family). All numbers below
were recounted from the merged meta sidecars on `main`; the
authoritative narrative is the final comparison comment on #106.

Token economics (9 prompts with flash-era meta; melon-jelly flash
predates the sidecar convention):

| Metric | GLM 5.3 Flash | GLM 5.2 |
|---|---|---|
| reasoning tokens | 221,533 | 228,233 (of which melon-jelly alone: 102,551 ≈ 45%) |
| completion tokens | 564,982 | 404,335 |
| retries | 6 | 5 |

Across the 9 comparable prompts GLM 5.2 burns ~0.57x flash reasoning
and ~0.51x flash completion.

Findings:

- **Zero truncations on both models in this tier.** The flash
  signature weakness (mid-expression cutoff racing the reasoning
  budget) did not manifest here.
- **GLM 5.2 is more reasoning-efficient on well-structured prompts**
  (horror-house: 13x reduction; last-flight: 14x; cities-skylines: 16x).
- **Physics/shader simulations flip the story** (melon-jelly: 102k
  rtok on 5.2; lava-lamp: 5.2 exceeds flash 43k vs 34k).
- **Different retry clustering**: flash retries concentrated on
  large-output prompts, 5.2's on reasoning-heavy physics/shader ones.
- **Comparable structural quality** — all artifacts brace-balanced;
  minor cosmetic flaws on 5.2 (one imbalanced block on
  cities-skylines, an unclosed fence on stillwater, a prose preamble
  on meridian-launch) are not truncations.

Definitive browser-verified playability (supersedes the earlier
boot-paint-era verdicts; see the DEFINITIVE comment on #106):

| Prompt | Flash | GLM 5.2 |
|---|---|---|
| melon-jelly | PLAYABLE_VERIFIED | PLAYABLE_VERIFIED |
| lava-lamp | BOOTS_ONLY | BROKEN_AT_BOOT |
| minecraft | BROKEN_AT_BOOT | BROKEN_AT_BOOT |
| sunset-ocean | PLAYABLE_VERIFIED | BROKEN_AT_BOOT |
| meridian-launch | BROKEN_AT_BOOT | PLAYABLE_VERIFIED |

Both models score 2/5 playable, but on different prompts: flash
handles shader-heavy scenes better (custom GLSL), 5.2 handles complex
multi-system assembly better. Neither dominates; failure modes are
complementary. The five blueprint-tier prompts (horror-house,
mario-kart, last-flight, cities-skylines, stillwater) were assessed
via materialize/build/smoke verdicts rather than the browser harness.

Status note: this covers all 10 prompts; the browser-verifier run
above completes the pending playability verification noted in the
earlier interim comparison.

(The flash column above quotes the earlier structural-verification

table.)

Honest caveats, carried verbatim from the sweep report:

- `reasoning_tokens` was not exposed by the gpt-oss-120b arm — the
  reasoning-budget difference is unmeasured; only completion length
  is a measured signal here.
- The verifier is mechanical and calibrated (it reproduces every
  known flash verdict from the #97 human audit), but BOOTS_ONLY vs
  BROKEN_AT_BOOT rests on a paint-spread threshold.
- meridian-launch's gpt-oss failure involved an `unpkg` import
  CORS-blocked in the verification environment — possibly
  environmental rather than a model fault; flagged as such.
- Deliverable shape follows the prompt TOML: HTML prompts yield
  single files, blueprint prompts yield markdown specs.

Repo policy unchanged: no runner or verifier code is committed
(engineless); helper scripts stayed outside the repo.
